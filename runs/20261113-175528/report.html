ehr-rest: why api_facade. MediCore EHR provides a structured REST API over HTTP with JSON endpoints for patients and conditions. Wrapping it with an API facade translates records on demand without duplicating data storage.
lab-sql: why database_polling. LabTrak LIS is an isolated SQLite relational database without an HTTP API, message feed, or change-data-capture stream. Read-only SQL polling on a scheduled interval is the most direct and least intrusive mechanism to extract patient demographics and laboratory result records.
adt-feed: why message_feed_ingest. The PAS emits real-time HL7 v2 event messages (ADT^A01, ADT^A03, ADT^A04) written as files. Ingesting and parsing these message events sequentially to construct and update Patient and Encounter FHIR resources fits the message feed ingest pattern.
pharmacy-csv: why file_drop_ingest. The system drops periodic flat CSV files (rx_export_*.csv) on a nightly schedule into a designated runtime directory. The file_drop_ingest pattern ingests these files and de-duplicates re-exported records across daily drops.
