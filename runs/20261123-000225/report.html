ehr-rest: why api_facade. MediCore EHR exposes a functional REST API (v2.3.1) with JSON pagination. An API facade allows querying data on demand and transforming responses into FHIR R4 resources without replicating storage.
lab-sql: why database_polling. LabTrak LIS is a legacy SQLite database with direct read-only SQL file access. It lacks an API or event messaging stream, making scheduled SQL polling the only suitable mechanism.
adt-feed: why message_feed_ingest. The ADT feed produces HL7 v2 event messages (ADT^A01, ADT^A03, ADT^A04) dropped as files representing discrete real-time registration, admission, and discharge business events. Standard message ingestion allows parsing HL7 v2 segments and updating Patient and Encounter resources statefully.
pharmacy-csv: why file_drop_ingest. The pharmacy system drops periodic flat files matching rx_export_*.csv. Reading the exports, deduplicating re-exported records across daily files (latest file wins), and translating to FHIR matches the file_drop_ingest pattern.
